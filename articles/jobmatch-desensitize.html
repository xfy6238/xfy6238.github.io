从私有 JD 库到脱敏开源：一次可展示的改造

阅读约 9 分钟 · 七类敏感点 · 20 条样例库设计 · 双模式 10/10
结论先行

脱敏不是删几个文件，而是另建一条可公开的平行线：原工程原地不动，新目录只装逻辑 + 虚构样例；评测脚本原样搬过去，rules / llm 双模式 10/10 即出厂合格证。

背景：为什么不能直接公开

一个求职匹配 Agent，天然带着三样不能见光的东西：真实公司名的 JD 库（来源合规风险）、个人画像（默认画像就是简历一句话）、密钥读取逻辑（读本地授权文件）。直接 push 等于同时泄露数据、身份和凭证。

但逻辑本身是干净的：检索排序走本地规则，大模型只做生成，Key 缺失自动降级。这意味着——把“数据”和“身份”抽掉，剩下的就是可开源的。改造目标就一句话：让陌生人 git clone 下来，五分钟跑通全链路。

1七类敏感点：先盘点再动手

动手前全仓扫一遍，敏感点归了七类，对应处置写死：

类别 例子 处置
真实 JD 数据 8 个真实 JSON、前端静态 jobs.json 副本 不带；只带 20 条虚构样例
运行时产物 jobs.db、向量库、日志 不带；gitignore
个人画像 默认画像、示例快捷画像、测试兜底数据里的真实公司 换成通用示例画像与虚构公司
密钥链路 读本地授权文件的演示脚本 重写，只走环境变量
爬虫与更新脚本 含真实姓名校验的抓取自动化 整文件不带；声明“无爬虫”
评测黄金集 含真实公司名的 20 条 RAG 黄金集 不带；10 题主评测改吃样例库
复盘报告 含内部路径与真实数据的 HTML 报告 不带；结论重写成博客文章

2样例库设计：20 条虚构，但要是“真数据”

样例库不是随便编 20 条——它要同时满足三件事：开箱可跑、评测全过、换真数据零改代码。设计要点：

  • 公司全虚构：名字一眼假（如“云杉示例科技”），链接全用 example.com 占位，避免与任何真实公司撞名。
  • 字段与真库同 schema：标题/公司/薪资/薪资中位/技能数组/fit/活跃度等一个不少，前端类型不用改。
  • 为评测量身定做：默认画像的 Top3 必须全员薪资≥17K、缺口命中 RAG/Prompt/MCP、热点命中——所以 3 个高优岗的技能要刻意铺好 RAG、Prompt、MCP、Docker 这些词；再掺两条 17K 以下的，演示过滤逻辑。
  • 技能必须是数组：缺口分析对技能做分词匹配，字符串会散成单字，这是从真库字符串格式里吃过的亏，样例里直接写对。
检验标准：换 JOBS_JSON 指向真库，代码一行不用改——样例库只是真库的“形状替身”。

3代码适配：最小改动六处

逻辑文件原样搬，只动与“私有”耦合的六处，每处都有明确理由：

  • JOBS_JSON 默认指向样例库（环境变量仍可覆盖）；
  • 默认画像换成通用示例画像；
  • 面试热点在无详情正文时回退扫标题+技能（详情库是私有数据，不能带）；
  • 评测脚本去掉“失败等两分钟重试”（那是双人协作的逻辑，开源版失败即打印快照退出）；
  • 一键演示脚本去掉个人密钥文件读取，只透传环境变量；
  • 会话库默认文件名改掉，不与任何真实库同名，防误覆盖。

4出厂合格证：双模式 10/10

评测脚本跟着样例库一起搬，跑两遍：纯规则模式（无 Key，即开箱状态）和大模型模式。两遍都 10/10 才算完——这意味着陌生人 clone 下来，不配任何密钥也能看到完整演示；配了 Key 则多出生成话术。

5提交前检查清单

  • 全仓 grep：真实公司名、招聘站 URL、真名、内部词、个人画像，零命中；
  • node_modules / dist / *.db / 向量库 / 日志 不在暂存区（git status 逐项过）；
  • 提交身份用 noreply 邮箱，不暴露公司邮箱；
  • 推送用一次性 Token，推完即删，remote 存干净地址；
  • 远端文件树与本地提交逐项对数（53 个文件，一个不少）。

成品在 jobmatch-agent 仓库。原私有工程原地不动，两条线从此各走各的：一条自用迭代，一条对外展示。
